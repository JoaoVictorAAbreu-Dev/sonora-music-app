# Decisions

Defaults chosen during implementation when the brief was silent or ambiguous. Each one is reversible.
The fixed decisions in the project brief (no Supabase, GCE VM + Docker Compose + Caddy, the listed stack,
auth model, Jamendo only through the API) are not repeated here.

| D2  | 2026-11-19 | `react-native-reanimated` **4.7.1** (+ `react-native-worklets`), not Reanimated 3.                                                                                                                                                                                                                                                                                               | Expo SDK 58 (current) pins Reanimated 4.7.1. | D5  | 2026-11-19 | Zod validation through a small `parse()` helper instead of a Fastify type-provider plugin.                                                                                                                                                                                                                                                                                       | One fewer dependency; the same shared error shape for every failure.                                                                                                                                                                 |

| D7  | 2026-11-19 | `GET /health` lives at the root; all other routes go under `/v1`.                                                                                                                                                                                                                                                                                                                | Uptime checks and Caddy health checks use a stable, unversioned path.                                                                                                                                                                |
| D8  | 2026-11-19 | Refresh token rotation: the consumed token gets `revoked_at` + `replaced_by` (its successor). (M2 replaced the M1 `family`/`used_at` columns.)                                                                                                         | Matches the M2 brief column names and makes the rotation chain auditable.                                                                                                                                                            |
| D9  | 2026-11-19 | `track_cache` is keyed by a generic `key` (`track:<id>`, `album:<id>`, `search:<hash>` …).                                                                                                                                                                                                                                                                                       | One cache table covers every proxied Jamendo request.                                                                                                                                                                                |
| D10 | 2026-11-19 | `playlist_tracks(playlist_id, position)` has a plain (non-unique) index; the API keeps positions contiguous inside a transaction.                                                                                                                                                                                                                                                | A unique constraint makes reordering need deferrable constraints, which Drizzle does not model.                                                                                                                                      |
| D11 | 2026-11-19 | Emails are unique case-insensitively (`unique index on lower(email)`).                                                                                                                                                                                                                                                                                                           | Avoids duplicate accounts that differ only by case; needed for account linking in M6.                                                                                                                                                |
| D12 | 2026-11-19 | Liquid Glass = `expo-glass-effect` `GlassView` on iOS 26+. Solid fallback (`bg.base` + hairline border, as in Figma) on Android, older iOS, and when Reduce Transparency is on.                                                                                                                                                                                                  | `GlassView` exists only on iOS 26+. Android blur via `expo-blur` needs `BlurTargetView` wiring; revisit in M7 if the Android look should be blurred.                                                                                 |
| D13 | 2026-11-19 | Inter is loaded at runtime from `@expo-google-fonts/inter` (400/500/600). The weight is encoded in the font family name.                                                                                                                                                                                                                                                         | Matches the Figma text styles without committing font files; avoids synthetic bold on Android.                                                                                                                                       |
| D14 | 2026-11-19 | Icons are the vector paths exported from Figma page "02 Ícones", rendered with `react-native-svg`.                                                                                                                                                                                                                                                                               | Keeps the custom icon set exact instead of substituting a generic icon font.                                                                                                                                                         |
| D15 | 2026-11-19 | The token drift test compares `packages/tokens` against a committed snapshot of the Figma variables (`figma-variables.json`, read through the Figma MCP). CI does not call Figma.                                                                                                                                                                                                | The Figma Variables REST API may need an Enterprise plan and a token in CI. Refresh the snapshot from Figma when variables change; the test then fails until code matches.                                                           |
| D16 | 2026-11-19 | Native colors in `app.json` are guarded by a test against the tokens. An ESLint rule rejects hex/rgb/hsl color literals in `apps/mobile`.                                                                                                                                                                                                                                        | `app.json` cannot import TypeScript; the lint rule enforces "no hard-coded colors". Spacing and durations are enforced by review (numbers cannot be linted reliably).                                                                |
| D17 | 2026-11-19 | Layout constants that are component measurements in Figma (tab bar 64, row 64, chip 36, icon–label gap 2, min touch 44, max font scale 2) live in `tokens.layout`.                                                                                                                                                                                                               | The "no hard-coded values" rule also covers these; they are not Figma variables, so they are not in the drift snapshot.                                                                                                              |
| D18 | 2026-11-19 | PostgreSQL 17 (alpine) for production, development and tests.                                                                                                                                                                                                                                                                                                                    | Current stable major; the same version everywhere.                                                                                                                                                                                   |
| D19 | 2026-11-19 | Backups use `pg_dump -Fc` and `gcloud storage cp` to a bucket; retention is a bucket lifecycle rule, not the script.                                                                                                                                                                                                                                                             | Restorable per table; no deletion logic in the script.                                                                                                                                                                               |
| D20 | 2026-11-19 | Auth rate limiting uses an in-memory fixed-window limiter (`AttemptLimiter`): per IP across all `/v1/auth/*` (default 30/min) and per email on login/register (default 10/15 min). `@fastify/rate-limit` was removed.                                                                                                                                                            | Its `groupId` keeps a separate counter per route with the local store, so a shared per-IP budget was not possible; per-email needs the parsed body anyway. One VM = one process, so memory is enough. Revisit if the API scales out. |
| D21 | 2026-11-19 | Error shape changed to `{ error: { code, message, details?, requestId? } }` with the M2 code set (`VALIDATION_ERROR`, `INVALID_CREDENTIALS`, `EMAIL_TAKEN`, `TOKEN_EXPIRED`, `TOKEN_REUSED`, `RATE_LIMITED`, plus `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `UPSTREAM_UNAVAILABLE`, `INTERNAL`). 4xx framework errors keep their HTTP status (e.g. 413) with `VALIDATION_ERROR`. | M2 brief. `requestId` kept for log correlation.                                                                                                                                                                                      |
| D22 | 2026-11-19 | Password policy: 10–128 characters and not in a short deny-list of common passwords (`packages/shared`). Login accepts any non-empty password up to 128. argon2id m=19 MiB, t=2, p=1 (OWASP baseline). Unknown emails are verified against a dummy hash.                                                                                                                         | M2 brief asks for min 10 (confirmed by the owner on 2026-11-19; Figma T03 updated to “mín. 10”). Upper bound limits hashing cost.                                                                                                    |
| D23 | 2026-11-19 | Sign-up requires `acceptTerms: true` (the T03 switch); the API stores `users.terms_accepted_at`. No display name at sign-up (T03 has no such field); `PATCH /v1/me` edits `displayName` only.                                                                                                                                                                                    | Consent is recorded server-side. Email change needs verification, which is out of M2 scope.                                                                                                                                          |
| D24 | 2026-11-19 | Registering an existing email returns `EMAIL_TAKEN` (409).                                                                                                                                                                                                                                                                                                                       | Required by the brief; it reveals that an email has an account. Login does not.                                                                                                                                                      |
| D25 | 2026-11-19 | Logout revokes the whole token family of the presented refresh token (that device's session) and is idempotent (204 for unknown tokens).                                                                                                                                                                                                                                         | Ends exactly one sign-in; other devices stay signed in.                                                                                                                                                                              |
| D26 | 2026-11-19 | Access token: HS256 JWT via `jose`, `iss=sonora-api`, `aud=sonora-app`, 15 min. Refresh token: 32 random bytes (base64url), stored as SHA-256, 30 days.                                                                                                                                                                                                                          | Opaque random tokens need no salt; HS256 is enough with a single issuer/verifier.                                                                                                                                                    |
| D27 | 2026-11-19 | App session: refresh token and last profile in `expo-secure-store` (`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`); access token in memory only. On launch the refresh token is rotated; offline launch keeps the cached profile and refreshes lazily. One in-flight refresh is shared by concurrent 401s; a failed refresh signs out.                                                   | M2 brief; offline relaunch should not log the user out.                                                                                                                                                                              |
